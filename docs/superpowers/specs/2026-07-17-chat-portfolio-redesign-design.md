# Редизайн портфолио: подача в формате чата

Дата: 2026-07-17

## Идея

Портфолио выглядит и ведёт себя как чат-приложение (в духе Claude/ChatGPT), но
никакого настоящего ИИ и никакой AI-персоны не изображает. Чат — это визуальный
и композиционный приём, а не продукт. Всё содержимое написано от первого лица,
как будто сам Ярослав отвечает вам напрямую. Диалоги срежиссированы (не живой
LLM), но нигде явно не подписаны как «сценарий» — это просто такой формат
подачи текста, как обычный лендинг использует секции.

Слева — список чатов (навигация), справа — сам диалог с содержанием: контекст
→ роль/процесс → результат, перемежающийся с картинками, метриками и чипами
навыков.

## Почему не третье лицо / не AI-агент

Рассматривали вариант «AI-гид по портфолио», рассказывающий о Ярославе в
третьем лице — отклонили: ощущается как лишняя выдуманная сущность между
посетителем и человеком. Решили проще: чат — просто интерфейсная метафора,
голос везде авторский, первое лицо, без упоминания бота или ИИ где бы то ни
было в UI.

## Структура сайдбара (слева)

```
┌────────────────────────┐
│ [YT]  Yaroslav Tarasov  │
│       ● Product Designer│
├────────────────────────┤
│ ○ Обо мне               │
├────────────────────────┤
│ ○ Мониторинг инфраструктуры   B2B · 2025
│ ○ Агроплатформа               AgTech · 2023–2024
│ ○ Product Roadmap [soon]      B2B · 2025
├────────────────────────┤
│ ○ Контакты               │
├────────────────────────┤
│ RU/EN            ↓ Резюме │
└────────────────────────┘
```

- Три секции, разделённые тонким дивайдером (1px, `--border`): «Обо мне»
  отдельно, кейсы вместе, «Контакты» отдельно.
- Каждый пункт: аутлайновая SVG-иконка (стиль Feather/Lucide, `stroke-width:
  1.8`, без заливки) + короткий заголовок + мета-строка (тег/год). Никаких
  эмодзи нигде в интерфейсе.
- Активный пункт подсвечен (фон + акцентный цвет иконки/текста).
- Заголовки в сайдбаре короткие (1–2 строки максимум) — короче полного
  названия кейса, которое uже даётся в шапке диалога справа, где больше места.
- Низ сайдбара: переключатель RU/EN, ссылка на скачивание резюме PDF.
- На мобильных сайдбар — выезжающая панель (drawer), скрыта по умолчанию,
  открывается по иконке гамбургера в шапке чата.

## Структура диалога (справа)

- Шапка: иконка + название чата + теги (домен/год).
- Сообщения идут парами: реплика посетителя (короткий пузырь, выровнен
  вправо, нейтральный серый фон) → ответ Ярослава (без пузыря, слева, с
  аватаром-инициалами «YT», основной контент).
- Ответ может включать: абзацы текста, картинку кейса с подписью, карточки
  метрик (для ISY: часы→минуты и т.п.), ряд чипов (навыки/технологии).
  Метрики и чипы верстаются только там, где есть реальный факт из текущего
  контента сайта — никаких выдуманных цифр.
- В конце ветки диалога — горизонтальный ряд из 2–3 кнопок-подсказок
  («Какая была твоя роль? →», «Следующий кейс: Агроплатформа →`) — это не
  свободный ввод, а фиксированная навигация по заранее написанным веткам.
- Внизу — честный CTA вместо декоративного поля ввода: кликабельная плашка
  «Написать мне в Telegram →», которая по клику открывает
  `https://t.me/yatarasov` в новой вкладке. Никакого текста про
  «срежиссированность» диалога — сам факт, что это не текстовое поле, а
  кнопка-ссылка, уже не вводит в заблуждение.

## Голос и позиционирование

- Первое лицо везде: «Я спроектировал…», «Меня зовут Ярослав Тарасов…».
- Реплики посетителя пишем на «ты» («Что ты умеешь?», «Какая была твоя
  роль?») — непринуждённый разговорный тон, без «вы».
- Никаких слов вроде «инфобез» — используем «мониторинг инфраструктуры»,
  «информационная безопасность» там, где нужно точное описание.
- Компания-работодатель (Kaspersky) не упоминается внутри кейса ISY — по
  просьбе, кейс описывается как внутренний B2B-продукт для мониторинга
  инфраструктуры. В чате «Обо мне» упоминание Лаборатории Касперского
  остаётся (это факт биографии, не специфика кейса).

## Визуальный стиль

Тёмная тема, чистая AI-чат эстетика (валидировано живым HTML-мокапом):

- Фон `#0d0d0f`, сайдбар `#131316`, границы `#26262b`.
- Текст: `#ececf1` основной, `#9b9ba5` вторичный, `#6b6b76` совсем тихий.
- Акцент `#6c8cff` (индиго/синий) — активные пункты сайдбара, ссылки, метрики.
- Аватар — градиент `#6c8cff → #a06cff`, круглый, инициалы «YT».
- Карточки (метрики, картинки) — `#1a1a1f`, скруглённые углы 12px, тонкая
  граница.
- Системный шрифт (`-apple-system, Segoe UI, Roboto…`), без кастомных
  веб-шрифтов — быстрее грузится, уже так на сайте сейчас.
- Framer Motion остаётся: лёгкое появление сообщений (fade + сдвиг по Y),
  hover-состояния на чипах и пунктах сайдбара — в духе текущей анимационной
  системы сайта.

## Контент по чатам

Контент собран из уже существующих данных сайта (`app/data/projects.ts`,
`app/cases/*/data.ts`, `app/cases/*/functions-data.ts`,
`i18n/translations.ts`) — ничего не выдумано, только пересобрано в формат
диалога и сокращено до сканируемого объёма (кейс — это не полный текст
текущей лонгрид-страницы, а 3–5 реплик с самым важным).

### «Обо мне» (роут `/`)

1. Приветствие + краткое позиционирование (из `hero.description` +
   `about.paragraph1`): продуктовый дизайнер 5+ лет, B2B, сложные системы,
   T1 → Kaspersky Lab, дашборды/внутренние платформы/данные.
2. Вопрос «Что ты умеешь?» → три направления (Product Design / Design
   Systems / Processes, из блока Skills) + ряд чипов навыков (как на
   мокапе).
3. Подсказки в конце: «Покажи лучший кейс →», «Где ты работал? →», «Как
   связаться? →».

### «Мониторинг инфраструктуры» (ISY, роут `/cases/isy-iseeyou`)

1. «Расскажи про этот проект» → что за продукт и зачем (единое окно для
   топ-менеджмента и ИБ-команды вместо ручных Excel-выгрузок), картинка
   `laptop-dashboard.png`.
2. «Какая была твоя роль?» → исследование (изучил ручной процесс,
   сегментировал аудиторию: C-level, комплаенс, security-team), архитектура
   (структура от общего к частному, система фильтров, визуальный язык
   рисков/статусов), переход с Angular на единую B2B дизайн-систему на React
   вместе с командой дизайн-системы. Опциональная вторая картинка
   (`table_filter.png` или `autocheck_card.png`).
3. «Для кого именно этот дашборд?» → 3–4 роли из `case.isy.roles.*` (CISO,
   руководитель подразделения, ИТ-оператор, аудитор) с задачей/результатом
   каждой — коротко, не все восемь ролей.
4. «И что получилось?» → карточки метрик: «Часы → минуты» (генерация
   отчётов), «1 окно» (вместо ручных выгрузок), «Real-time» (данные без
   ожидания).

### «Агроплатформа» (роут `/cases/agro-platform`)

1. «Расскажи про Агроплатформу» → платформа для управления агропредприятием:
   поля, культуры, планирование работ, урожайность; AI + спутник + метео +
   телеметрия (из `projects.agro.description`), картинка
   `agro-platform-hero.png`.
2. «Как ты подошёл к исследованию?» → сегментировал аудиторию (фермеры,
   агрономы, управляющие), интервью и наблюдение с агрономом, ключевые
   сценарии первой итерации (мониторинг полей, планирование, анализ
   урожайности).
3. «Что получилось спроектировать?» → пять модулей платформы кратко:
   управление полями (карта + NDVI/EVI/NDMI), мониторинг культур
   (севооборот), технологические карты (диаграмма Ганта), телеметрия
   техники, AI-ассистент по агрономии — оформить как чипы/список, 1–2
   картинки (`fields-management.png`, `gantt.png`).
4. «Валидировал с пользователями?» → собрал фидбек по эскизам и прототипам,
   интервью и демо с агрономом и стейкхолдерами, встроил правки в следующую
   итерацию.

Метрик с точными цифрами по этому кейсу в текущих данных нет — числа не
придумываем, ограничиваемся списком функций.

### «Product Roadmap» (роут `/cases/product-roadmap`, помечен `[soon]`)

**Предположение, требует подтверждения:** в коде уже есть полный текст кейса
(`app/cases/product-roadmap/page.tsx`), но на сайте он до сих пор помечен
`comingSoon: true` и не открывается по клику. Сохраняем текущее поведение —
чат-версия тоже остаётся тизером, а не полным диалогом:

1. Короткое приветствие: что это за инструмент (roadmap для согласования
   релизов и планирования на год, из `projects.productRoadmap.description`).
2. Сообщение о том, что подробный кейс с процессом и результатами готовится
   к публикации (текст на основе `projectCard.comingSoonDescription`).

Если это предположение неверно и кейс пора открыть полностью — контент для
полной версии (4 этапа процесса, before/after, роадмап-структура) уже есть
в `page.tsx` и может быть переверстан в чат-сценарий по той же схеме, что и
ISY/Агро.

### «Контакты» (новый роут `/contact`)

Не диалог, а одна карточка-сообщение: короткий текст (на основе
`contact.title`/`contact.description`) + две крупные кнопки — «Написать в
Telegram» и «LinkedIn» — и ссылка на резюме PDF.

## Технические решения

- Стек не меняется: Next.js 16 (App Router, `output: 'export'`), React 19,
  Tailwind, Framer Motion. Деплой (GitHub Actions → GitHub Pages,
  `yaroslavtarasov.com`) не трогаем.
- Сайдбар выносится в `app/layout.tsx` (или общий клиентский layout-компонент
  `ChatShell`), чтобы не перемонтироваться при переходах между роутами —
  переключение чатов ощущается мгновенным, без перезагрузки сайдбара.
- Роуты сохраняются как отдельные страницы (как сейчас): `/`,
  `/cases/isy-iseeyou`, `/cases/agro-platform`, `/cases/product-roadmap`,
  плюс новый `/contact`. Это даёт прямые ссылки на конкретный кейс и не
  меняет структуру, к которой уже привязан GitHub Pages / SEO.
- Активный пункт сайдбара подсвечивается по текущему пути
  (`usePathname()`).
- Контент чатов описывается как данные (по образцу уже существующих
  `getTimelineSteps(language)` в `app/cases/*/data.ts`): функция
  `getChatScript(language)`, возвращающая массив сообщений вида
  `{ role: 'visitor' | 'author', blocks: Block[] }`, где `Block` — один из
  `paragraph | image | metrics | chips | suggested`. RU/EN — как и сейчас,
  через `LanguageContext`.
- Существующие тексты кейсов (`data.ts`, `functions-data.ts`,
  `translations.ts`) используются как источник контента; сами длинные
  markdown-лонгриды (`page.tsx` кейсов) заменяются чат-версткой и
  перестают рендериться в текущем виде.
- Компоненты, которые больше не нужны в текущем виде (`Header.tsx`,
  `Timeline.tsx`, `CaseTimeline.tsx`, грид `ProjectCard.tsx` на главной) —
  ревизия и, где не используется, удаление — решается по ходу реализации,
  не фиксируется заранее пунктом за пунктом.
- `ImageModal.tsx` можно оставить для увеличения картинок по клику внутри
  диалога — не обязательно, но простое улучшение поверх существующего кода.

## Вне рамок этого этапа

- Живой ИИ/LLM для реальных ответов — сознательно не делаем (см. решение
  выше про срежиссированный формат).
- Пароль-защищённые кейсы (`password` в модели `Project`) — поле есть в
  типах, но не используется ни одним кейсом сейчас; не проектируем UI под
  него заново, просто не ломаем существующий тип.
- Полное раскрытие кейса Product Roadmap — см. предположение выше.
